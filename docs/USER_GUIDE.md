# Руководство пользователя

[К оглавлению](../README.md)

## 1. Назначение и подготовка

Рабочий режим этой версии — eMMC через XGecu T48. USB-код зависит от Windows и WinUSB. Готовый EXE содержит Python и ресурсы интерфейса; установка Python для его запуска не нужна. Драйвер USB и корректное аппаратное подключение остаются необходимыми.

Подключайте чип через подходящий для вашей схемы адаптер/ISP. Документация проекта не содержит подтверждённой универсальной распиновки для всех корпусов, таблицы напряжений VCC или инструкции установки драйвера для всех ревизий T48. Используйте схему адаптера и документацию чипа. Настройка VCCQ в GUI сама по себе не подтверждает фактическое измеренное напряжение.

Перед восстановлением сохраните исходные данные, если они нужны. Запись, стирание и часть настроек EXT_CSD изменяют память; автоматического отката нет. Не запускайте одновременно штатную утилиту Xgpro и операции этого приложения с одним T48.

## 2. Начальные настройки

| Элемент | Начальное значение | Значение |
|---|---|---|
| Режим | eMMC | NAND/SPI пока не реализованы |
| VCCQ 1.8V | Включено | Флаг выбора напряжения интерфейса; не настройка ёмкости |
| Шина | 4-bit | Также можно выбрать 1-bit |
| Пресет | Авто | Подбор перед первой операцией, затем кеш |
| Частота в Авто | Авто | Ручной выбор заблокирован |
| Верификация после чтения | Выключена | Повторное чтение и сравнение с сохранённым файлом |
| Верификация после записи | Включена | Чтение после перезапуска и сравнение с образом |
| Стирать перед записью | Включено | Стирается вся выбранная область |
| Тема | Тёмная | Переключатель «Светлая тема» |

Настройки и кеш автоподбора хранятся в памяти процесса. Сохранение пользовательского профиля между запусками не реализовано. Низкоуровневые функции Python имеют собственные значения параметров: например, `verify=False` и `erase_before=False`; значения GUI не следует переносить на прямые вызовы API.

## 3. Инициализация

Нажмите «Инит eMMC» на вкладке чтения или записи. Кнопки запускают один сценарий:

1. Сбрасывается кеш «Авто», очищаются журнал, таблица и прежние сведения о размерах.
2. Открывается T48, применяется настройка подключения.
3. В режиме «Авто» выбираются пресет и частота.
4. Читаются регистры, формируется отчёт, опрашивается статус RPMB.
5. В User Area ищется GPT/MBR, таблица заполняется найденными разделами.
6. Сохраняется снимок EXT_CSD с CID для последующей работы с настройками.

Отсутствие GPT/MBR допустимо для пустой или стёртой памяти. Оно не означает, что чип не определился. Проверьте CID, название, ёмкость и сообщения об ошибках отдельно.

Отчёт показывает производителя, модель, дату, версию, оценки ресурса, возможности DEVICE_TYPE и размеры. Эти сведения зависят от декодирования регистров. В частности, GPP1–GPP4 в текущем отчёте выводятся как 0 без вычисления реальных размеров. Диагностика RPMB не является чтением его содержимого или проверкой подлинности ключа.

## 4. Пресеты и частота

Доступны «стандартный», «THGA» и «Авто». Название THGA обозначает набор параметров T48, а не автоматическое подтверждение производителя любого установленного чипа.

В ручном режиме доступны 8, 16, 20, 30 МГц; для THGA дополнительно «30 МГц (эксп.)». Обычные 30 МГц используют High-Speed (`HS_TIMING=1`), экспериментальные THGA — Legacy (`HS_TIMING=0`). Для 30 МГц код требует включённую VCCQ 1.8 V. 40 МГц отсутствуют.

«Авто» сначала получает эталон на 8 МГц, затем перебирает более быстрые варианты. Ошибки отдельных кандидатов с последующим успешным выбором — нормальная часть подбора. Алгоритм подробно описан в [архитектуре](ARCHITECTURE.md).

Подобранный режим используется следующими сессиями при совпадении VCCQ/ширины шины. Новый подбор запускается кнопкой «Инит eMMC» либо при отсутствии подходящего кеша. **После замены чипа нажмите «Инит eMMC»**: кеш не привязан к CID и сам замену не обнаруживает.

## 5. Чтение и резервная копия

### Отдельные области

- «BOOT1» и «BOOT2» читают соответствующие аппаратные загрузочные области. Размер определяется по EXT_CSD.
- «Чтение Userdata» сохраняет всю User Area от LBA 0 до последнего сектора.
- «Дамп» в строке таблицы читает включительный диапазон LBA данного раздела. Строка таблицы GPT/MBR также доступна для дампа.

Файл сохраняется в выбранном месте. Данные читаются потоком, а не загружаются целиком в оперативную память. Убедитесь, что файловая система назначения допускает нужный размер; например, FAT32 не подходит для больших дампов.

### Полное чтение

«Полное чтение (BOOT1 + BOOT2 + Userdata)» запрашивает папку и последовательно создаёт:

```text
Boot1.bin
Boot2.bin
userdata.img
```

Если хотя бы один из этих файлов уже существует, полный сценарий прекращается до чтения. Выберите другую папку. При ошибке одного этапа следующие не запускаются. EXT_CSD и RPMB не входят в эти три файла.

### Верификация чтения

При включённом флаге после сохранения каждой области eMMC перезапускается, область читается повторно и сравнивается с файлом. Это увеличивает время и USB-трафик примерно на повторное чтение проверяемых данных, без гарантии фиксированного коэффициента.

После STOP или ошибки файл может остаться частичным. Имя файла и его наличие не подтверждают успешное завершение. Проверяйте итоговый журнал и размер.

## 6. Запись

### Выбор образов

Сначала выполните инициализацию для получения ёмкостей. На вкладке «Запись» выберите рабочую папку или задайте файлы вручную через «Файл...».

Автопоиск использует имя файла либо имя без расширения без учёта регистра:

| Назначение | Распознаваемая основа |
|---|---|
| BOOT1 | boot1 |
| BOOT2 | boot2 |
| User Area | userdata |
| EXT_CSD | extcsd, ext_csd, ecsd_csd |

Поиск не рекурсивный. Например, `Boot1.bin` подходит, а `boot1_backup.bin` автоматически не выбирается. При неоднозначности выберите файл вручную. Ручное назначение имеет приоритет. «Обновить файлы» повторяет проверку наличия и размера; она также выполняется перед записью.

Пустой файл, превышение области или выход округлённого последнего блока за её границу блокируют запись. Меньший образ допускается с предупреждением.

**Для строк BOOT1/BOOT2/Userdata используйте RAW-образы.** Здесь файл записывается как последовательность байтов; Android Sparse не разворачивается. Частичный Sparse-парсер относится к записи диапазона из таблицы и имеет существенные ограничения.

### Отдельная область

Проверьте путь и статус строки, флаги стирания/верификации и нажмите «Записать». При включённом стирании порядок такой: анализ образа → стирание всей области → контроль стирания → запись полезных блоков → перезапуск → верификация всего файла.

Если образ меньше области, стирание удалит и остаток за ним. При отключённом стирании данные за образом в общем случае сохраняются, но последний передаваемый блок дополняется до 16 КиБ; подробнее в [операциях](OPERATIONS.md).

### Полная запись

Для «Записать чип» нужны все три готовых файла BOOT1, BOOT2 и Userdata. Последовательность: BOOT1 → BOOT2 → User Area → выбранный EXT_CSD. Если EXT_CSD отсутствует, записываются только образы. Если выбранный EXT_CSD некорректен или его изменения не подтверждены, полная запись не запускается.

Ошибка образа или верификации останавливает дальнейшие этапы. Уже записанные области не восстанавливаются автоматически. Настройки EXT_CSD предварительно проверяются до образов и применяются после них. Особое поведение при несовпадении EXT_CSD readback описано в [отдельном документе](EXT_CSD.md).

## 7. Стирание

На вкладке стирания доступны вся User Area, BOOT1, BOOT2 и пользовательский диапазон LBA. Адреса вводятся в десятичном виде, начальный и конечный секторы включены. Размер сектора — 512 байт.

Для всей User Area программа определяет конечный LBA по ёмкости. Для BOOT автоматически подставляется его размер, но до инициализации GUI может использовать резервное значение 8192 сектора. Сначала прочитайте сведения о чипе.

Ручное стирание и предварительное стирание перед записью — разные реализации. Ручное стирание не выполняет контрольное чтение; при тайм-ауте готовности оно логирует ошибку, но может продолжить и вывести общий успех. Поэтому при ошибке в журнале считать стирание подтверждённым нельзя. Подробности — в [диагностике](TROUBLESHOOTING.md).

## 8. EXT_CSD

На вкладке записи таблица показывает «Чип», «Файл», «Новый» и действие для полей 177, 178, 179, 162, 160. Снимок чипа появляется после инициализации. Выбор файла заполняет значения файла и проекта изменения, но не подменяет прочитанные данные чипа.

Поле 160 только читается. Значения новых байтов задаются в HEX. Перед изменениями требуется актуальный аппаратный снимок, совпадение настроек подключения и подтверждение диалога. Необратимые свойства RST_n/защиты и форматы файлов описаны в [EXT_CSD](EXT_CSD.md).

## 9. STOP / СБРОС

STOP устанавливает запрос отмены. При чтении и обычном ожидании USB отменяются pending transfers. Во время объявленного потока записи отмена USB откладывается: приложение завершает текущий пакет до 1 МиБ, получает статус и останавливается перед следующим.

Это не аварийное мгновенное отключение питания и не отмена уже записанных/стёртых данных. Пока операция завершается, дождитесь освобождения интерфейса. При аппаратном зависании фактическое время может превышать измеренные в тесте 1.55–1.77 с.

## 10. Журнал и оформление

Журнал имеет время до миллисекунд, подсветку и уровни «Все», INFO, OK, WARN, ERROR. Поиск выполняется без учёта регистра. Фильтр меняет отображение, а «Копировать» копирует полный исходный журнал, включая скрытые фильтром строки. «Очистить» очищает журнал, «К последним» включает следование за новыми строками.

Процент и скорость относятся к текущей фазе. Для оптимизированной записи скорость может учитывать логически пройденные пропуски и быть выше фактической скорости USB. Успех определяйте по результатам операции и верификации в журнале, а не только по 100%.

«Инит eMMC» имеет фон `#AFFC41` в светлой теме и `#548C2F` в тёмной, с белым текстом в тёмной. Выпадающие списки разделены линиями. Окно называется Xgecu Prog; строгий знак микросхемы используется как иконка окна и EXE.
