# EXT_CSD: снимки, сравнение и изменение настроек

[К оглавлению](../README.md)

## 1. Что представляет регистр

EXT_CSD — 512 байт расширенных параметров eMMC: ёмкость, возможности, режимы, загрузочные настройки, защита и оценки ресурса. Это не обычный раздел с образом. Приложение читает весь регистр, но записывает только явно разрешённые отдельные байты через CMD6 WRITE_BYTE.

Смещения полей в интерфейсе и описании десятичные, значения байтов — HEX. В HEX-дампе слева смещение шестнадцатеричное. Многобайтовые числовые поля интерпретируются little-endian.

Снимок считывается после инициализации: BUS_WIDTH[183], HS_TIMING[185] и доступ к области могут уже отличаться от состояния после включения питания целевого устройства.

## 2. Файлы и происхождение данных

`load_file` принимает ровно два формата:

| Размер | Содержимое |
|---|---|
| 512 байт | RAW EXT_CSD |
| 544 байта | EXT_CSD 512 + CID 16 + CSD 16 |

Текстовый HEX-дамп не является этим форматом. Файлы иной длины отклоняются. Из файла 544 байта настройки извлекаются только из первых 512; хвост сохраняется отдельно. Хвост не записывается как регистр и не заменяет текущую аппаратную идентификацию.

Внутренний CID сессии — ответ T48 длиной 32 байта; его нельзя без преобразования считать тем же форматом, что 16 байт CID в хвосте файла.

Таблица GUI различает:

- **Чип** — свежий снимок, полученный от оборудования.
- **Файл** — значения выбранного файла для сравнения.
- **Новый** — проект значения для применения.

Открытие файла до чтения оборудования не делает его доверенным снимком чипа. Для записи требуется инициализация или чтение EXT_CSD с подключённого устройства. В коде сохранены методы чтения/открытия/сохранения/сравнения регистра; наличие метода не означает отдельную доступную кнопку в текущем GUI. Отдельная вкладка EXT_CSD отсутствует, основные пять полей размещены на вкладке записи.

## 3. Разрешённые поля

| Смещение | Имя | Работа приложения |
|---|---|---|
| 177 | BOOT_BUS_WIDTH | Чтение и валидируемая запись |
| 178 | BOOT_CONFIG_PROT | Чтение, установка допустимых битов защиты |
| 179 | PARTITION_CONFIG | Чтение, настройка загрузки с сохранением PARTITION_ACCESS |
| 162 | RST_N_FUNCTION | Чтение, подтверждённая попытка изменения |
| 160 | PARTITIONING_SUPPORT | Только чтение |

Запись остальных полей через пользовательский API запрещена. Полное копирование всех 512 байтов EXT_CSD на другой чип не выполняется. Код требует `EXT_CSD_REV[192] >= 3` для разрешённых записей.

### PARTITION_CONFIG[179]

Биты 2:0 — PARTITION_ACCESS, биты 5:3 — BOOT_ENABLE, бит 6 — BOOT_ACK. Бит 7 зарезервирован. Приложение разрешает BOOT_ENABLE 0, 1, 2 или 7. При ручной записи PARTITION_ACCESS должен остаться прежним; при построении плана из файла эти биты принудительно берутся из текущего снимка.

Выбор BOOT для доступа к данным и выбор области загрузки устройства — разные операции. Файл-образ BOOT1 не устанавливает автоматически BOOT_ENABLE.

### BOOT_BUS_WIDTH[177]

Отклоняются зарезервированные старшие биты и зарезервированные комбинации ширины/режима. Это настройка загрузочной шины eMMC, а не переключатель текущей ширины USB-обмена T48 из верхней панели GUI.

### BOOT_CONFIG_PROT[178]

Разрешены только биты 0 и 4. Снять уже установленную защиту записью меньшего значения нельзя. Установка постоянной защиты требует явного подтверждения. Если текущая защита блокирует изменение загрузочных настроек, изменения 177/179 отклоняются.

Постоянную защиту нельзя считать обратимой настройкой профиля. При записи плана защита применяется последней, чтобы не заблокировать предшествующие изменения.

### RST_N_FUNCTION[162]

Разрешены 00, 01, 02: исходное состояние, включение, отключение RST_n. Изменение требует подтверждения; 01/02 могут фиксироваться необратимо. Чип вправе отклонить изменение уже установленного значения или возврат к 00.

Readback байта подтверждает значение регистра. Он не доказывает физическую работу вывода RST_n; отдельная аппаратная проверка вывода не выполнена.

### PARTITIONING_SUPPORT[160]

Поле только читается, кнопка записи заблокирована. Оно описывает поддержку функций разбиения, но не включает их записью произвольного значения. Создание GPP и enhanced-разделов в этой версии не реализовано.

## 4. Запись одного поля

1. Получить аппаратный снимок и CID.
2. Выбрать поле, ввести байт HEX.
3. Проверить, что настройки VCCQ, шины, пресета и частоты не изменились после снимка.
4. Подтвердить диалог с CID и переходом старое → новое.
5. В рабочей сессии повторно проверить CID и актуальность исходного значения.
6. Выполнить CMD6 и прочитать EXT_CSD повторно.

Неизменившееся значение не записывается повторно. При ошибке состояние GUI требует нового чтения регистра; не следует считать черновик подтверждённым аппаратным результатом.

Программный параметр `allow_otp=True` означает, что вызывающая сторона уже получила необходимое подтверждение; его не следует включать без понимания эффекта.

## 5. Применение файла и полная запись

`write_plan(current, target)` заранее проверяет все планируемые изменения на копии текущего снимка. Порядок: **177 → 179 → 162 → 178**, одинаковые значения исключаются. Поле 160 игнорируется при записи, PARTITION_ACCESS сохраняется.

Перед стартом полного восстановления проверяются CID и актуальность полей 177/178/179/162. Для 179 при этой проверке сравниваются старшие пять битов (`mask=0xF8`), потому что доступ к аппаратной области может меняться во время операций.

Полная последовательность:

```text
проверка выбранного EXT_CSD
    ↓
BOOT1 → BOOT2 → User Area
    ↓
повторная проверка EXT_CSD/CID
    ↓
177 → 179 → 162 → 178
```

Подтверждение плана выполняется до старта. Если образы завершились с ошибкой, EXT_CSD не применяется. Если STOP поступил в процессе настроек, часть полей уже могла измениться.

## 6. Особое правило readback

При отличии прочитанного байта от запрошенного приложение пишет «Ошибка верификации EXT_CSD», сохраняет фактически прочитанный снимок и продолжает применение следующего поля. Это заданное поведение, отличающееся от верификации RAW-образа, где несовпадение блокирует успех операции.

В конце плана выводится сообщение о завершении с ошибками верификации, если значения не совпали. `_apply_extcsd_file` при таких несовпадениях всё равно возвращает True; поэтому общий итог полной записи может появиться и после предупреждения EXT_CSD. **Проверяйте сообщения по каждому полю и итог настроек; общий успех полной операции не гарантирует совпадение всех настроек EXT_CSD.**

Ошибки транспорта, CMD6, изменения CID/снимка и невозможность прочитать регистр не превращаются в обычное несовпадение и не должны считаться подтверждением записи.

## 7. Остальные отображаемые сведения

Модуль `extcsd.py` умеет описывать версии, DEVICE_TYPE, SEC_COUNT, BOOT/RPMB, защиту, режимы шины, группы стирания, enhanced/GPP-параметры, reliable write, BKOPS, cache, native sector size, ресурс и CMDQ. Это справочное декодирование; оно не означает поддержку соответствующих операций приложением.

Сравнение двух снимков показывает все различающиеся байты и их имена. Отличия volatile-параметров после init не обязательно означают повреждение. Нули в поле не доказывают поддержку или отсутствие функции вне контекста версии eMMC.
