# AGENTS.md — работа с Xgecu Prog

## 1. Назначение и область действия

Этот файл содержит инструкции для агентов и разработчиков, работающих с текущей версией Xgecu Prog в каталоге `emmc_continue` и его подкаталогах. Он не заменяет задачу пользователя и не распространяет автоматически разрешение на операции с оборудованием.

Рабочий язык общения и пользовательской документации — русский. Сохраняйте существующие имена API и технических полей на английском. Основная точка входа — `gui.py`, основной файл сборки — `T48_eMMC.spec`.

Документ составлен по состоянию на 30 октября 2026 года. Состояние тестов и оборудования меняется: перед выводами проверяйте актуальный код и результаты. Не превращайте исторические наблюдения в постоянные гарантии.

В родительском каталоге и соседних `new`, `new_gui`, `patch_thga_test`, `reverse`, `OR` могут находиться другие версии и исходные материалы. Не переносите туда изменения автоматически и не запускайте одноимённый родительский `gui.py` вместо этой версии.

Ранее `emmc_continue` был неотслеживаемым каталогом Git. Проверяйте текущий статус; отсутствие файла в diff не доказывает отсутствие изменений на диске. Не выполняйте массовый `git add`, очистку untracked-файлов, reset или удаление артефактов без относящейся к задаче причины и необходимого разрешения.

## 4. Порядок работы

1. Уточните фактический результат, который нужен пользователю, по текущему запросу и принятым решениям.
2. Проверьте существующие изменения и прочитайте связанные методы/привязки.
3. Внесите минимальное законченное изменение в соответствующий слой.
4. Выполните относящуюся к изменению существующую проверку; при ошибке разберите конкретную причину.
5. Если изменилось поведение, обновите соответствующие docs. При запросе готового EXE пересоберите его.
6. Сообщите, что изменено, что реально проверено и что осталось неподтверждённым.

Не расширяйте задачу новыми режимами, зависимостями или переработкой архитектуры без необходимости. Не переписывайте рабочий код ради единообразия. Не исправляйте посторонние падения молча: отделяйте их от регрессии своей правки.

Сохранение файла, сборка, запуск GUI, тест на mocks и аппаратная верификация — разные результаты. Называйте именно выполненный уровень проверки.

## 6. Основные функциональные инварианты

### 6.1. Области и адреса

- Userdata в GUI означает **всю аппаратную User Area**, а не только Android-раздел userdata.
- Ёмкость User Area берётся из `SEC_COUNT[212:216]`, размер каждой BOOT — из `BOOT_SIZE_MULT[226]`.
- Сектор — 512 байт, порция T48 — 16 КиБ/32 сектора.
- Диапазоны LBA включают оба конца: `(end - start + 1) × 512`.
- Запись передаёт полные порции; последний неполный блок дополняется 00 до 16 КиБ.
- Проверяйте округлённую передачу, а не только исходный размер образа.

### 6.2. Полные операции

- Полное чтение/запись: BOOT1 → BOOT2 → User Area.
- Выбранный EXT_CSD применяется после образов.
- Полная запись требует все три образа; EXT_CSD необязателен, но некорректный выбранный файл нельзя молча игнорировать.
- До образов выполняется предварительная проверка выбранного плана EXT_CSD.
- Ошибка образа/его верификации останавливает следующие этапы.
- Полное чтение не перезаписывает уже существующие Boot1.bin/Boot2.bin/userdata.img в выбранной папке.
- EXT_CSD и RPMB не входят автоматически в три файла полного чтения.

### 6.3. Стирание и пропуски

- В GUI стирание перед записью и верификация записи включены по умолчанию.
- Стирается вся выбранная область, включая остаток после меньшего образа.
- Контроль стирания: весь диапазон до 32 МиБ, иначе первые 32 МиБ.
- Пропуск RAW-заполнения 00/FF разрешён только после предварительного стирания и его контроля.
- Ожидаемое заполнение берётся из ERASED_MEM_CONT[181], а не угадывается по образу.
- Без стирания нули и FF являются данными и должны передаваться.
- Верификация RAW сравнивает весь файл, включая пропущенное заполнение.
- Остаток области за концом меньшего файла в верификацию образа не входит.

Не заменяйте ошибку контроля стирания предупреждением с последующей записью. Не выдавайте контроль первых 32 МиБ за проверку пустоты всей большой области.

### 6.4. Форматы

Полная запись аппаратных областей — RAW. Частичный Sparse-парсер используется в маршруте диапазонов таблицы. FILL не разворачивается, DONT_CARE пропускается, CRC не проверяется. Верификация выбранных RAW-сегментов не подтверждает весь развёрнутый Sparse.

Не заявляйте полноценную поддержку Sparse без реализации семантики всех нужных чанков и проверки логического результата. Исправление Sparse требует отдельного анализа границ, заполнения, ошибок формата и проверки конечных данных.

## 7. STOP, потоки и USB

Сохраняйте текущую модель владения: рабочий поток выполняет операцию и освобождает её USB-дескрипторы; GUI устанавливает запрос отмены.

- `run_task` сериализует задачи через `_operation_lock`.
- `usb_operation(stop_event)` связывает экземпляры устройства с событием рабочего потока.
- `cancel_operation` отменяет pending USB только вне `_write_active`.
- Объявленный поток записи должен получить все обещанные порции и статус завершения.
- Пакет записи ограничен 64 порциями/1 МиБ; STOP проверяется перед следующим пакетом.
- Нельзя обрывать активный поток немедленным AbortPipe или ранним выходом между его порциями.
- `begin_write` согласован с STOP общей блокировкой; флаг снимается в `finally` ожидания завершения.
- Короткая отправка USB — ошибка, а не успешная частичная запись.
- Короткий USB-блок/хвост чтения — ошибка, а не нулевые данные.
- При ошибке power-off USB всё равно должен освобождаться.

Измеренные 1.55–1.77 с STOP относятся к конкретным испытаниям; не используйте их как гарантированный максимум. Не добавляйте бесконечные повторы и не увеличивайте тайм-ауты вместо локализации ошибки.

## 8. Перезапуск перед верификацией

Текущий специальный recovery относится только к OSError 121 при **чтении ответа на отправленную команду power-off**. После него закрываются/открываются USB-дескрипторы, выполняются init, чтение регистров и сравнение CID. Затем всё равно нужен полный предусмотренный readback.

Не расширяйте этот catch на всю верификацию, запись команд или произвольные USB-ошибки. Ошибка отправки, другой код, невозможность открыть T48, init failure, смена CID или несовпадение данных должны оставаться ошибками.

В финальном `close` предупреждение power-off скрыто по принятому решению, но освобождение USB обязательно. Не возвращайте повторяющееся предупреждение без причины, относящейся к задаче. При этом не утверждайте, что отсутствие сообщения доказывает физическое снятие питания.

## 9. Автоподбор и частоты

- Пресет «Авто» — начальный выбор GUI.
- Эталон получается на 8 МГц с проверкой регистров и данных.
- Кандидаты проверяются по CID/CSD, геометрии и повторному чтению начала/середины/конца User Area.
- Автоподбор не стирает и не записывает пользовательские области.
- Успешный init без чтения не достаточен для принятия кандидата.
- Кеш процесса учитывает VCCQ/шину и используется следующими сессиями.
- «Инит eMMC» явно сбрасывает кеш и запускает новый подбор.
- Кеш не привязан к CID; после замены чипа требуется новый init.
- Настройки существующей сессии не меняются при переключении GUI для следующей операции.

Рабочие частоты: 8, 16, 20, 30 МГц. Для 30 код требует VCCQ 1.8 V. THGA Legacy 30 (`HS_TIMING=0`) остаётся экспериментальным разгоном выше паспортного предела Legacy 26 МГц. High-Speed 30 и Legacy 30 — разные варианты.

**40 МГц исключены по решению пользователя. Не возвращайте их в приложение в рамках обычного исправления.** Успех архивного опыта на другом CID не даёт основания включать режим для текущего чипа.

Частота, физическая ширина шины и напряжения не измерены прибором. Не называйте их инструментально подтверждёнными по одному значению selector или EXT_CSD.

## 10. EXT_CSD и необратимые настройки

Разрешённые пользовательские записи: 177, 178, 179, 162. Поле 160 только читается. Не добавляйте произвольную запись остальных байтов под видом восстановления 512-байтного файла.

- Форматы файла: ровно 512 или 544 байта.
- Файл не подменяет свежий снимок подключённого чипа.
- Перед записью проверяются CID, исходное значение и соответствие настроек подключения.
- PARTITION_ACCESS в поле 179 сохраняется.
- План из файла: 177 → 179 → 162 → 178, защита последней.
- RST_N_FUNCTION и постоянная защита требуют соответствующего подтверждения.
- `allow_otp=True` предполагает уже полученное подтверждение вызывающей стороной.
- Readback RST_N_FUNCTION не доказывает физическую работу RST_n.

Принятое поведение: несовпадение readback отдельного разрешённого поля логируется, фактический снимок сохраняется, план продолжается. Не превращайте его незаметно в успех и не меняйте правило продолжения без запроса. Транспортные ошибки и смена CID не должны маскироваться этим правилом.

Общий итог полной записи может следовать за предупреждениями EXT_CSD. В отчётах указывайте несовпавшие поля отдельно, не называйте весь набор настроек подтверждённым.

## 11. Работа с реальным оборудованием

Разделяйте действия:

| Действие | Требование |
|---|---|
| Чтение кода/логов, mocks, сборка, запуск GUI без операции | Обычная работа по задаче |
| Init/read-only probe | Проверить занятость T48, параметры и влияние volatile-настроек |
| Запись/стирание eMMC | Нужно применимое разрешение на конкретный чип/область; проверьте контекст и сохранность данных |
| OTP/постоянная защита | Подтверждение конкретных изменений; сохранять диалоги защиты |
| Перепрошивка T48 | Отдельное изменение самого программатора; прежнее разрешение писать eMMC его не покрывает |

Ранее пользователь разрешал тестовые записи на установленный пустой чип и проверки 8/30 МГц. Не считайте это доказательством, что любой будущий чип всё ещё пустой, и не требуйте повторного согласования для уже явно разрешённого неизменившегося сценария.

Перепрошивка T48 отклонена. Offline-кандидаты в firmware_candidates не устанавливать, bootloader-переходы не запускать без нового явного изменения этого решения пользователем.

Не запускайте аппаратную проверку одновременно с активной GUI-операцией. Сначала выполняйте доступную проверку чтением. В аппаратном отчёте фиксируйте CID, область, LBA, длину, режим, хеши и реальный результат. Не считайте счётчик отправленных байтов доказательством программирования.

## 12. GUI и визуальные требования

- GUI-состояние меняется через поток Kivy/Clock, без прямых обновлений виджетов из USB-потока.
- Журнал, числовой прогресс и фаза передаются отдельными callback.
- При смене темы сохраняйте контраст активных/неактивных состояний.
- «Инит eMMC»: светлая тема `#AFFC41`, тёмная `#548C2F`, текст тёмной темы белый.
- Все SpinnerOption имеют разделительные линии.
- Кнопка «Scatter -> GPT» удалена; наличие старого метода не является поводом вернуть её.
- Название окна — Xgecu Prog.
- Выбран строгий логотип: logo_technical.svg; иконки xgecu_prog.png и xgecu_prog.ico.
- NAND/SPI показываются как режимы в разработке, не как работающие функции.
- Поиск/фильтр журнала не должен уничтожать исходные строки; копирование включает полный журнал.

В тестах реактивного GUI при необходимости используйте `Clock.tick()` и `Builder.sync()`. Не полагайтесь только на обычный `walk()` для виджетов неактивных Screen. Не фиксируйте устаревший цвет вместо актуальной семантики темы.

## 13. Команды и окружение

Из каталога emmc_continue в PowerShell:

```powershell
..\venv\Scripts\python.exe -X utf8 gui.py
..\venv\Scripts\python.exe -X utf8 smoke_layers.py
..\venv\Scripts\python.exe -X utf8 smoke_stop.py
..\venv\Scripts\python.exe -X utf8 smoke_verification.py
..\venv\Scripts\python.exe -X utf8 smoke_autoconfig.py
..\venv\Scripts\python.exe -X utf8 smoke_extcsd.py
```

Каждый smoke запускайте отдельным процессом: они меняют глобальные настройки и создают GUI. Они используют mocks/fixtures и не являются разрешением запускать аппаратные probe-скрипты.

Проверенное окружение: Python 3.11.6 x64, Kivy 2.3.1, PyInstaller 6.22.3, Pillow 13.0.0. Полная таблица — BUILD.md. Корневой requirements.txt не является lock-файлом сборки. Не обновляйте все зависимости ради несвязанной локальной правки.

В этой среде `rg` в PowerShell не найден. Используйте доступные специальные grep/glob-инструменты или ограниченный поиск средствами Python/PowerShell; не повторяйте неработающую команду. Для inline Python с кириллицей учитывайте кодировку pipeline; используйте UTF-8 либо файл скрипта. Не создавайте вспомогательные скрипты, если достаточно одного безопасного вызова.

## 17. Незавершённые возможности и честные формулировки

Известные ограничения нельзя скрывать исправлением документации:

- Полный Sparse не реализован.
- Ручное стирание не выполняет readback и может продолжить после тайм-аута готовности.
- Диапазонная запись без стирания имеет более слабую защиту границ.
- GPT CRC/backup и EBR не проверяются/не обходятся полностью.
- ФС определяются по сигнатурам, без монтирования.
- GPP в отчёте фиксированы нулями; общих операций GPP нет.
- RPMB — пробный статус, без полного authenticated API.
- Полной успешной аппаратной верификации образа 3 ГиБ нет.
- После исправления restart аппаратно сравнивались 4 МиБ BOOT1 до/после перезапуска; это не полный повтор записи всех областей.
- Частоты/ширина физически не измерены.
- Нет постоянных профилей, автоматической версии, полного lock-файла и гарантии воспроизводимости EXE.

Если задача исправляет одно из ограничений, обновите код, проверку и документацию согласованно. Не представляйте планируемую функцию как уже реализованную.
